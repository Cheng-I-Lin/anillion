# Data provenance and permitted use

Research date: November 5, 2026. Gameplay and builds are offline. No anime API is called at runtime, no mass scraping is enabled, and no LLM generates facts or validates answers.

## Reviewed anime TV metadata

The expanded catalog contains **81 named Japanese anime television adaptations** selected from a bounded editorial research list. Wikidata's read-only search was used to disambiguate TV series from manga, franchise umbrella items, films, live-action adaptations, seasons, and English dubbing items. Only selected TV entities entered the runtime catalog. For example, the 2011 `Hunter × Hunter` entity is distinct from the 1999 adaptation, and `Tamayura: Hitotose` is distinct from the earlier OVA.

Factual metadata was retrieved in small batches from the [Wikidata Action API](https://www.wikidata.org/w/api.php). The research snapshot in [`data/wikidata-reviewed.json`](data/wikidata-reviewed.json) retains entity IDs, labels, aliases, source URLs, retrieval date, factual date values, genre/production-company IDs, and statement IDs. `src/data/anime.json` contains the reviewed subset needed by the game, with separately assigned editorial prominence estimates. No copyrighted biographies, encyclopedia prose, posters, or screenshots were imported.

| Runtime field                       | Source and interpretation                                                                                                                                                                                                                                          |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `wikidataId` and canonical identity | Reviewed TV entity from the search result; no automatic merge with its source manga.                                                                                                                                                                               |
| Name and aliases                    | English labels/aliases, plus explicitly curated common English/romanized alternatives.                                                                                                                                                                             |
| `firstYear`                         | Earliest year in the TV entity's start-time claims (`P580`), or publication-date claims (`P577`) when no start-time claim was present. Date precision was checked before extracting a year; the resulting years were reviewed against the selected TV adaptations. |
| `genres`                            | Direct `P136` IDs. The game exposes a named subset of the source taxonomy; missing genre fields are not inferred. Prompts explicitly refer to catalog tags.                                                                                                        |
| `productionCompanies`               | Direct `P272` IDs. **A production company is not necessarily the animation studio.** Prompts say “catalog production credits” rather than silently treating a broadcaster or producer as an animator.                                                              |
| `prominence`                        | Editorial gameplay estimate; not a Wikidata field, external popularity measurement, or player percentage.                                                                                                                                                          |

The [Wikidata licensing policy](https://www.wikidata.org/wiki/Wikidata:Licensing) releases structured data in its data namespaces under **CC0**. The [data-access guidance](https://www.wikidata.org/wiki/Wikidata:Data_access) describes API access, meaningful User-Agent headers, avoiding unnecessary concurrent load, and honoring error and rate-limit responses. This permits keeping the bounded factual snapshot. It does not license linked third-party artwork or prose.

Research requests identified the project, used bounded sequential searches and small entity batches, and stopped on request errors rather than retrying indefinitely. The initial maxlag-enabled request reported replication lag; the subsequent bounded read-only discovery and entity lookups were used for editorial research, not a continuous ingestion service. There is no automated refresh job or permanent-storage dependency on a service with unverified terms.

Genre claims and production credits are incomplete and sometimes broader than viewers' informal categories. The catalog therefore does not claim to exhaust every valid genre/studio relationship. Unsupported episode totals, source demographics, and inferred studio roles do not generate prompts. All eligible questions must also pass the rarity and answer-count gate, regardless of the amount of metadata available.

## Curated character facts

`src/data/characters.ts` has **216 canonical characters** across ten franchises, with English/romanized names, aliases, memberships, and source references. It expands the starter roster with less prominent supporting characters rather than upgrading popular characters to fill a Legendary slot. Facts and editorial prominence estimates remain separate.

Some official pages are image-heavy, JavaScript-driven, or block automated fetches. References support manual factual checking, not a licensed exhaustive character API. Romanized aliases and memberships remain editorially maintained; the collection is not a complete franchise database. Old fine-grained faction prompts are not admitted simply because membership fields exist: they must meet the same broad-answer/full-rarity gate as every other scope.

Generated character-era/genre/credit questions join a roster to an explicit TV-entity ID. Their reveal sources include both the character reference and the TV metadata reference supporting the predicate. A missing or disputed answer can be flagged with its displayed question, scope, and rules version; flags are local and exportable.

## Sources not imported

**AniList:** its [API terms](https://docs.anilist.co/guide/terms-of-use) restrict using the API as a data-storage/backup service and direct commercial developers to contact AniList. Its [rate-limit documentation](https://docs.anilist.co/guide/rate-limiting) currently shows a degraded temporary limit alongside the normal limit. No AniList payloads or popularity fields are stored. A future integration needs an explicit current terms/retention/commercial review; API availability is not permission for bulk permanent ingestion.

**MyAnimeList/Jikan:** the [official MAL v2 documentation](https://myanimelist.net/apiconfig/references/api/v2) and current caching/retention terms could not be fully verified in this environment. No availability guarantee, numeric rate limit, storage permission, or scraping permission is assumed. No MAL/Jikan pipeline exists. A proxy is not a substitute for permission from the underlying source.

## Future data changes

Before adding another source, record its exact endpoint/entity mapping, current availability, license, commercial and retention constraints, rate-limit behavior, and provenance. Review uncertain fields instead of filling them by guesswork. Update the snapshot/data version and run the whole-bank audit and tests. New facts expand possible scopes automatically; the engine never lowers its rarity gate to manufacture more questions.
